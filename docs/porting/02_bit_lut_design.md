# Enhanced128 LUT 및 비트 설계 세부 분석

## 1. 고정소수점(Fixed-Point) 포맷 선택 근거

| 포맷 | 정밀도(LSB) | 다이내믹 레인지 | LUT 메모리(256엔트리) | 장단점 |
|------|-------------|----------------|-----------------------|---------|
| **Q8.8**  | 0.0039 | ±255 | 512B  | 메모리 최소, 정밀도 부족 |
| **Q12.4** | 0.0625 | ±2048 | 512B  | 저주파 함수 적합, 고주파 손실 |
| **Q16.16** | 1.5×10⁻⁵ | ±32768 | **1 KB** | 정밀도/범위 균형, CPU 시프트 최적 | 
| Q20.12 | 2.4×10⁻⁴ | ±1 M | 1 KB | 고정밀 저주파, 곱셈 시 64비트 필요 |

프로젝트 목표(RMSE 0.01) 달성을 위해 **Q16.16** 포맷을 표준으로 채택한다.

## 2. LUT 해상도 결정

`basis_id` 수행 함수별로 요구되는 최대 Nyquist 주파수를 Legacy 분석에서 추출하였다.

| basis_id | 함수 | 주요 주파수 성분 | 최소 샘플 수 | 선택된 엔트리 수 |
|---------|------|----------------|--------------|----------------|
| 0–3 | Sin/Cos × Sinh/Cosh | ≤ π | 128 | **256** (2× 안티에일리어싱) |
| 4–7 | Bessel J/I/K/Y | 비선형 고주파 | 256 | **512** |
| 8 | TanhSign | 저주파 | 64 | **256** (정규화 용이) |
| 9 | Sech × Tri | 중주파 | 128 | **256** |
| 10 | ExpSin | 중-고주파 | 256 | **512** |
| 11 | Morlet(ω=5) | 5 Hz 대역 | 128 | **256** |

LUT 크기를 2ⁿ 단위로 맞추기 위해 **256** 또는 **512** 엔트리를 사용하며, 모든 함수 LUT는 `Vec<u16>`(Q16 값)으로 직렬화한다.

## 3. 비트-필드 상세 설계

```
┌──────────── hi (64b) ────────────┐┌──────────── lo (64b) ────────────┐
│63          48 47           32 31│…│63      40 39                 12 11│…│0│
│ differential_cycle   reserved   │ │      r(24)        θ(28)     basis │
└─────────────────────────────────┘└────────────────────────────────────┘
                                       │11-8 │7-4 │3-1 │0
                                       │basis │rot │log │d_r
                                       │  id  │code│2_c │
```

### 3.1 hi 필드 (64비트)
* **differential_cycle(16b)**: 11비트 미분 사이클 + 5비트 여유(미래 확장).
* **reserved(16b)**: 메타데이터(버전, 체크섬 등) 보관.

### 3.2 lo 필드 (64비트)
| Bit | 길이 | 설명 | 비고 |
|-----|-----|-----|-----|
| 63-40 | 24 | `r_bits` | r ∈ [0,0.9999] → Q0.24 정규화 |
| 39-12 | 28 | `θ_bits` | θ ∈ [0,2π) → Q0.28 |
| 11-8  | 4  | `basis_id` | 0-11, 예비 4개 |
| 7-4   | 4  | `rot_code` | 0-15: 각도 = rot_code·π/8 |
| 3-1   | 3  | `log2_c` | -4~+3, 편의상 3비트 2’s complement |
| 0     | 1  | `d_r` | 0:0차, 1:1차 |

## 4. LUT ⟨→ Q16.16⟩ 직렬화 프로세스

```rust
fn serialize_lut(values: &[f32]) -> Vec<u16> {
    values.iter().map(|&v| (v * 65536.0).round() as u16).collect()
}
```
* 모든 LUT는 범위 구간을 `[0,1]`(r) 또는 `[0,2π)`(θ)로 매핑 후 균등 샘플.
* 압축: Zstd 레벨 3 → 약 40% 절감, 빌드 시 `build.rs`에서 자동 압축/해제.

## 5. 고정소수점 곱셈/시프트 규칙

| 연산 | 입력 Q | 출력 Q | 구현 |
|------|--------|--------|-----|
| LUT 조회 | Q16 | Q16 | 테이블 직접 반환 |
| 곱셈 | Q16×Q16 | Q16 | `(a as i32 * b as i32) >> 16` |
| 덧셈 | Q16+Q16 | Q16 | i32(actor) 합산 후 `& 0xFFFF` |
| 야코비안 | Q16×Q16 → Q16 | 미리 LUT |

## 6. LUT 메모리 예산

| 구분 | 엔트리 | 크기(Q16) | 함수 수 | 합계 |
|------|-------|----------|---------|------|
| 256-entry | 256 | 512B | 6 | 3 KB |
| 512-entry | 512 | 1 KB | 2 | 2 KB |
| **총** | — | — | — | **5 KB** |

빌드 시 `.rodata` 섹션에 상수로 포함되므로 실행 시 추가 메모리 사용 없음.

## 7. 디코딩·연산 파이프라인

1. **비트 마스킹**: `lo`·`hi`를 시프트/마스크로 파라미터 추출.
2. **고정소수점 변환**: r, θ를 `u32` 로 유지(시프트만 사용).
3. **좌표 계산**: `x,y → r_local,θ_local`을 정수 산술 + LUT(atan2 근사).
4. **LUT 조회**: basis 값, 야코비안 값 모두 Q16 획득.
5. **미분 비트 적용**: `hi` 사이클로 `+/-`, `스왑` 등의 부호·시프트 결정.
6. **최종 곱셈**: Q16 고정소수점 곱셈 2회, 시프트 2회.

## 8. 예상 계산량 비교

| 항목 | 현재(Hash) | Enhanced128(LUT) |
|------|-----------|------------------|
| 정수 XOR/AND | 8 | 4 |
| 정수 곱(32×32) | 1 | 2 |
| LUT 조회 | 0 | 2 |
| 분기(branch) | 0 | 1 (basis switch) |
| **CPU cycles(예상)** | 35 | 50 |

속도 손실 < **1.5×**, 반면 RMSE 50× 향상(0.5→0.01) 예상.

## 9. 결론

* **Q16.16 + 256/512 엔트리 LUT** 조합으로 정확도와 메모리 균형 확보.
* `Enhanced128` 비트 필드 설계는 Legacy의 모든 수학적 요소를 표현하면서도 128비트 예산을 초과하지 않음.
* 계산량 증가가 제한적이므로 고속 서빙 목표를 유지 가능.
